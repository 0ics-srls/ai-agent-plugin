# TypeScript — The generated client and the typed load

How `branches/frontend.md` 1-3 are written: the client generated from the API's OpenAPI document,
and the load of an entity typed from its request.

---

## 1. Generation

- The client is generated by Orval (MIT) from `openapi/<Api project>.json`, the file the API's test
  keeps equal to the served document. `orval.config.mjs` at the frontend's root:

  ```js
  export default {
    api: {
      input: "../openapi/App.Api.json",
      output: {
        target: "src/api/api.ts",
        schemas: "src/api/model",
        client: "angular", // or "react-query", "vue-query", "fetch" — the framework's overlay says which
        mode: "tags-split", // one folder per tag: one per entity
        clean: true,
      },
    },
  };
  ```

- `src/api/` is generated code: in `.gitignore`, ignored by ESLint, checked by the
  compiler. `npm run generate` (`orval --config orval.config.mjs`) runs before the gate, the tests and
  the build — the scripts `precheck`, `pretest` and `prebuild` call it — so they always see the client
  of the current document, a fresh clone included.
- One function (or method, or hook) per operation, named by the operation's id
  (`Customers_GetById` → `customersGetById`); the models are the API's types with their names as is.
- With the `fetch` client every answer is typed by its status — `{ status: 200; data: Customer } |
  { status: 404; data: ProblemDetails } | { status: 400; data: ProblemDetails }` — and the code narrows
  on `status`. Every failure is the API's one error format, a `ProblemDetails` with the code of the
  domain in `Code` (`api.md` 5).
- The calls are relative to the application's origin: in development the framework's dev server
  proxies `/api` to the backend, in production the same origin serves both. A client that runs
  elsewhere (a test in Node) sets `baseUrl: { runtime: "process.env['API_URL'] ?? ''" }`: the
  expression is read at every request.

## 2. The typed load

This section, `prime.md` and `devextreme.md` hold when the API's load speaks the DevExtreme data
protocol — the C# backend (`overlays/csharp/aspnetcore.md` §3), or a Rust one (`overlays/rust/service.md`). On a backend in another language, the
frontend calls the list operations the client generates, with the load options and the result types
that backend declares in its contract; the rest of this file holds as written.

The load of an entity answers rows, the fields `Select` asks, or groups, as the request says
(`api.md` 3). The contract documents the result as `LoadResultOf<Entity>`, so the generated call
carries the entity; the base computes from the request the exact type of `data`. It is written once,
in `src/app/shared/load/load.ts` (or the framework's shared folder), and holds no type assertion.

```ts
import type { DataSourceLoadOptionsBase, LoadGroup, ProblemDetails } from "../../../api/model";

// Four levels of nesting, counted by the length of a tuple.
type Limit = [unknown, unknown, unknown, unknown];
type Nested<V> = NonNullable<V> extends readonly unknown[] ? never : NonNullable<V> extends object ? NonNullable<V> : never;

/** Every field path of T, the nested ones with a dot: 'Amount', 'Customer.Name'. */
export type Path<T, Seen extends unknown[] = []> = Seen extends Limit
  ? never
  : { [K in keyof T & string]-?: K | ([Nested<T[K]>] extends [never] ? never : `${K}.${Path<Nested<T[K]>, [...Seen, unknown]>}`) }[keyof T & string];

type Head<P extends string> = P extends `${infer H}.${string}` ? H : P;
type Rest<P extends string, K extends string> = P extends `${K}.${infer R}` ? R : never;

/** T with only the selected paths, nested objects kept: what the server returns for Select. */
export type Selected<T, P extends string> = {
  [K in keyof Pick<T, keyof T & Head<P>>]: K extends P
    ? T[K]
    : null extends T[K]
      ? Selected<NonNullable<T[K]>, Rest<P, K & string>> | null
      : undefined extends T[K]
        ? Selected<NonNullable<T[K]>, Rest<P, K & string>> | undefined
        : Selected<T[K], Rest<P, K & string>>;
};

export type Operator = "=" | "<>" | "<" | "<=" | ">" | ">=" | "contains" | "notcontains" | "startswith" | "endswith";
export type Condition<T> = readonly [Path<T>, Operator, string | number | boolean | null];
export type Filter<T> = Condition<T> | readonly ["!", Filter<T>] | readonly (Filter<T> | "and" | "or")[];
export interface SortBy<T> { readonly Selector: Path<T>; readonly Desc?: boolean }
export type Interval = "year" | "quarter" | "month" | "day" | "dayOfWeek" | "hour" | "minute" | "second" | number;
export interface GroupBy<T> { readonly Selector: Path<T>; readonly Desc?: boolean; readonly GroupInterval?: Interval }
export interface SummaryOf<T> { readonly Selector: Path<T>; readonly SummaryType: "sum" | "min" | "max" | "avg" | "count" }

/** The load options, every field checked against the entity. */
export interface LoadRequest<T> {
  readonly Skip?: number; readonly Take?: number;
  readonly RequireTotalCount?: boolean; readonly RequireGroupCount?: boolean;
  readonly IsCountQuery?: boolean; readonly IsSummaryQuery?: boolean;
  readonly Filter?: Filter<T>; readonly Sort?: readonly SortBy<T>[]; readonly Group?: readonly GroupBy<T>[];
  readonly Select?: readonly Path<T>[];
  readonly TotalSummary?: readonly SummaryOf<T>[]; readonly GroupSummary?: readonly SummaryOf<T>[];
}

/** A group: its key, how many rows, its summaries; the inner level's groups, never rows. */
export interface GroupOf<I> { key: LoadGroup["key"]; items: I; count?: number; summary?: (number | null)[] }
/** A group of a request whose levels are known only at run time. */
export interface AnyGroup { key: LoadGroup["key"]; items: AnyGroup[] | null; count?: number; summary?: (number | null)[] }

type Row<T, R> = R extends { readonly Select: readonly (infer S extends string)[] } ? Selected<T, S> : T;
type Groups<G> = G extends readonly [unknown, ...infer Tail] ? GroupOf<Tail extends readonly [] ? null : Groups<Tail>[]> : never;

/**
 * What data holds for the request R on the rows of T: a request written in the code gives the exact
 * shape; a request a component builds at run time, which may or may not group, gives rows or groups.
 */
export type LoadData<T, R> = R extends { readonly Group: infer G extends readonly [unknown, ...unknown[]] }
  ? Groups<G>[]
  : "Group" extends keyof R ? Row<T, R>[] | AnyGroup[] : Row<T, R>[];
export interface Loaded<D> { data: D; totalCount: number; groupCount: number; summary?: (number | null)[] }

/** A generated load call with its answers: the result, or the ProblemDetails. */
export type LoadCall = (options?: DataSourceLoadOptionsBase | null) => Promise<{ status: number; data: { data: readonly unknown[] } | ProblemDetails }>;

/** The entity a generated load call lists, read from its result. */
export type EntityOf<C extends LoadCall> =
  Exclude<Awaited<ReturnType<C>>["data"], ProblemDetails> extends { data: infer D } ? (D extends readonly (infer X)[] ? Exclude<X, LoadGroup> : never) : never;

/** The failure the server answered: its status and its ProblemDetails, with the code of the domain. */
export class LoadError extends Error {
  public readonly status: number;
  public readonly problem: ProblemDetails;
  public constructor(status: number, problem: ProblemDetails) {
    super(`${String(status)} ${problem.Code ?? ""}: ${problem.detail ?? problem.title ?? ""}`);
    this.status = status;
    this.problem = problem;
  }
}

// The request as the generated body: the same names, the arrays copied out of their readonly form.
const body = <T>(request: LoadRequest<T>): DataSourceLoadOptionsBase => {
  const { Filter: filter, GroupSummary: groupSummary, Group: group, Select: select, Sort: sort, TotalSummary: totalSummary, ...flags } = request;
  return {
    ...flags,
    ...(filter && { Filter: [...filter] }), ...(sort && { Sort: [...sort] }), ...(group && { Group: [...group] }),
    ...(select && { Select: [...select] }), ...(totalSummary && { TotalSummary: [...totalSummary] }),
    ...(groupSummary && { GroupSummary: [...groupSummary] }),
  };
};

/** Runs the load; the overload declares that the shape of data follows the request, as the server's protocol does. */
export async function load<C extends LoadCall, const R extends LoadRequest<EntityOf<C>>>(call: C, request: R): Promise<Loaded<LoadData<EntityOf<C>, R>>>;
export async function load(call: LoadCall, request: LoadRequest<unknown>): Promise<unknown> {
  const { data, status } = await call(body(request));
  if (!("data" in data)) {
    throw new LoadError(status, data);
  }
  return data;
}
```

`load(ordersLoad, { Select: ["Amount", "Customer.Name"], Take: 10 })` is typed
`Loaded<{ Amount?: number; Customer?: { Name?: string } | null }[]>`; with
`Group: [{ Selector: "Status" }]` it is `Loaded<GroupOf<null>[]>`; `Select: ["Nope"]` does not
compile. This is the `fetch` form; the framework's overlay gives the form of its own client, with the
same types.

A field a component names at run time — the sort or the filter of a grid, of a table — becomes a
`Path` only when the view declared it. The check is written once, in `src/app/shared/load/fields.ts`,
and the request of every UI library goes through it:

```ts
import type { Path } from "./load";

/** The declared field a component named, or undefined. */
export const fieldOf = <T>(fields: readonly Path<T>[], name: unknown): Path<T> | undefined => fields.find(field => field === name);
```

## 3. Proving it

- The types are proved with `expectTypeOf(...).toEqualTypeOf<...>()` (Vitest), checked by the
  compiler, and `@ts-expect-error` on the property a request must refuse.
- The behaviour is proved against the real API: each shape — rows, `Select`, `Group` on one and two
  levels, the count — and a refusal arriving as `LoadError` with the server's `ProblemDetails`.
